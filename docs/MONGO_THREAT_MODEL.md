# Pharma Care MongoDB Migration Threat Model

**Phase:** 1 — design only  
**Status:** Proposed controls; implementation and testing have not started.  
**Scope:** Browser, Nginx/web container, Fastify API, MongoDB replica set, Docker network, backup volume, and operational access in the planned single-shop-per-user multi-tenant design. Threats are not claims that current code is vulnerable.

| # | Threat | Likely impact | Specific design control |
|---:|---|---|---|
| 1 | **Authentication bypass** through missing guards, forged claims, inactive users, suspended shops, or trusting stale JWT roles | Unauthorized access or privilege escalation | Register auth and active-shop hooks on every protected Fastify route; public routes are an explicit allowlist. Verify JWT signature, issuer, audience, expiry, and algorithm; reload active user/role/permissions from Mongo for authorization; reject inactive/deleted users and suspended shops. Default deny, route guard tests for every endpoint, short-lived access tokens, generic failures. |
| 2 | **Cross-shop IDOR / tenant escape** via guessed IDs, request-supplied `shopId`, unscoped joins/lookups, or exports | Disclosure/modification of another pharmacy's data | Derive `shopId` only from authenticated server-side user; prohibit it in Zod request DTOs; centralize scoped repository filters requiring `shopId`; include it in every business unique/query index; scope parent and referenced-ID checks on every operation; return indistinguishable not-found errors. Add two-shop isolation tests for every route family and transaction. |
| 3 | **NoSQL operator injection** using `$ne`, `$where`, dotted keys, prototype properties, or malicious sort/filter objects | Auth bypass, data exfiltration, unintended updates | Parse request DTOs with strict Zod schemas (`strict()`); accept scalar values/enum sort names only; construct Mongo filters/updates in server code, never spread request objects into queries; reject `$`/`.` field names and prototype keys; disable server-side JavaScript; test operator payloads against all query/mutation routes. |
| 4 | **Cost/profit leakage** in list/detail/export, error, log, receipt, label, QR, print snapshot, nested object, or cashier response | Confidential supplier economics exposed to cashier/customer | Define per-route, per-role response DTO allowlists and separate cost-bearing DTO types; project only necessary fields; prohibit raw document serialization; use a cost-free receipt/label schema; strip cost fields before logs/exports; assert recursive absence of cost/profit/margin keys in Cashier, print, receipt and error contract tests. |
| 5 | **Stock race conditions / oversell / duplicate financial writes** from concurrent checkout, return, adjustment, retries, or double-click | Negative stock, broken balances, duplicate sale/payment | Use replica-set Mongo multi-document transactions with snapshot reads and majority writes; perform conditional stock decrements (`remaining >= needed`) and recheck FEFO eligibility inside transaction; write stock movement, sale/return/ledger/counter/audit together; retry only whole transactions on transient labels; enforce `Idempotency-Key` uniqueness and payload fingerprint. Load-test competing checkouts against the same batch. |
| 6 | **Access/refresh token theft, replay, fixation, or session persistence** | Account takeover and unauthorized API operations | Access token lifetime 15 minutes; refresh token cryptographically random, HttpOnly, Secure, SameSite cookie, rotated on every use, stored only as a cryptographic hash, revocable by session family; detect reuse and revoke family; TLS only; no tokens in localStorage, URLs, logs, error payloads, or analytics; logout and password reset revoke refresh families. |
| 7 | **Brute force / credential stuffing** against login, reset, or refresh endpoints | Account takeover, user lockout or API denial of service | Per-IP and per-normalized-account rate limits with bounded windows; exponential throttling and temporary lock after repeated failures; generic login errors to prevent account enumeration; argon2id password hashes with tuned memory/time parameters; password reset rate limit and audit; monitor failed attempts without logging password or token. |
| 8 | **Stored/reflected XSS in product labels, receipts, memo, customer text, or print-request snapshots** | Session actions, malicious print content, data theft | Escape text by output context in HTML generation; prefer DOM/text APIs and fixed templates; validate/sanitize allowed URL schemes and image sources; do not insert raw HTML from API/DB; use restrictive CSP at Nginx; sanitize/allowlist print snapshot fields server-side; regression tests with HTML, quote, URL, and SVG payloads in labels, memo and receipts. |
| 9 | **Mass assignment / over-posting** of role, permission, `shopId`, balance, status, cost, audit, or ownership fields | Privilege escalation, financial manipulation, tenant reassignment | Each route has a strict allowlisted Zod input DTO; mutation builders explicitly set each mutable field; server derives shop, actor, role, permission, price, totals, balances, statuses, and audit values; separate admin-only commands and role checks; reject unknown keys. Tests attempt every protected field on create/update/import routes. |
| 10 | **Log leakage** of passwords, access/refresh tokens, cookies, customer data, cost fields, or raw bodies | Credential compromise, privacy and business-data disclosure | Pino redaction for authorization/cookie/password/token/secret fields; log only request ID, route, actor/shop IDs where justified, result code and safe timing; never log raw body, Mongo query, DTO, or transaction document; generic external errors; access-control and retention policy for logs; tests assert redaction. |
| 11 | **Backup leakage, tampering, or unusable recovery** from backup volume, credentials, object copies, or restore process | Persistent data breach or irrecoverable data loss | `mongodump --gzip` backup stays on a protected volume; encrypt backups at rest and in transit with separately managed/rotated keys; least-privilege backup credentials; no public backup endpoint; restrictive filesystem/volume ACLs; retention and integrity manifests; monitor completion; scheduled restore drills to isolated scratch replica set verify collection counts/indexes/business invariants; never log secrets. |
| 12 | **Exposed MongoDB port or unauthorized container-network access** | Direct database compromise or bypass of API rules | Mongo listens only on the internal Compose network with no `ports` mapping; require Mongo authentication and replica-set internal auth key; separate least-privilege API, backup, and admin DB users; firewall only intended HTTPS/SSH ingress; production compose healthchecks/restart/resource limits; inspect rendered Compose and host listeners before release. |
| 13 | **Dependency/supply-chain vulnerabilities** in Node, Fastify plugins, Mongo driver, base images, or build dependencies | Remote code execution, auth bypass, data theft | Pin supported Node 22 base image by version/digest; lockfile, minimal direct dependencies, review plugin trust; automated dependency and container image scanning in CI; update policy and security advisories triage; no `npm install` at runtime; non-root API/web processes and read-only filesystems where possible; build provenance and image tags. |
| 14 | **CSRF** against cookie-authenticated refresh/logout or any cookie-authenticated mutation | Cross-site session rotation or unintended state change | Use `SameSite=Strict` where compatible (otherwise Lax with explicit CSRF token); verify Origin/Referer against configured public origin for state-changing cookie-authenticated endpoints; require custom CSRF header; reject simple content types; CORS exact-origin allowlist with credentials disabled except required cookie endpoints; never use GET for mutation. |
| 15 | **SSRF** through image/logo fetches, URL fields, import integrations, webhook or preview features | Access to cloud metadata, internal services, Mongo/API, or attacker endpoints | Do not fetch caller-provided URLs server-side; use uploaded/approved assets or strict URL allowlists; if fetching is required, block private/link-local/loopback/reserved IPs after DNS resolution, revalidate every redirect and DNS change, limit protocols/ports/size/time, and egress-filter containers. No user-controlled webhook/URL fetch route without a separate review. |

## Cross-cutting security requirements

- MongoDB credentials, JWT secrets, refresh-cookie keys, backup encryption keys, and TLS material are supplied only at runtime from environment/secret management. `.env` stays ignored, examples contain fake values only, and secrets are never baked into images or printed.
- Production browser traffic terminates HTTPS at the reverse proxy; proxy forwards `/api` only to the API service. MongoDB has no public port, browser route, or web-container connection.
- Validate every method/path/query/body, enforce request size and timeouts, and return generic errors without stack traces. Apply security headers, CSP, strict CORS, and rate limits.
- Keep audit logs append-only and redact them like all other operational telemetry; access to audit data is permission-scoped and shop-scoped.
- Use explicit API response schemas and tests for every role; test negative authorization, cross-shop identifiers, malformed BSON/ObjectId inputs, cost-key absence, concurrent writes, idempotency replays, refresh-token reuse, and safe error/log output.
- Threat controls remain design intentions until implemented and verified by tests, container inspection, and restore/security exercises.
